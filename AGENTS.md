# Правила совместной работы над iPod

## Указания пользователя и журнал команды

- Новые задания читайте в /Users/user/Desktop/промпт.txt перед началом, перед правками и перед завершением этапа. Не очищайте и не редактируйте этот файл.
- Общий журнал — /Users/user/Desktop/чат.txt. Только дописывайте в конец; не удаляйте и не переписывайте чужие записи. Записывайте время, роль, проверенные факты, затронутые файлы и статус.
- Вопросы пользователю записывайте в /Users/user/Desktop/вопросы.txt.
- Главный агент объединяет результаты и интегрирует изменения. Остальные агенты сначала проверяют назначенную область на чтение и передают выводы координатору.
- Один редактор на файл за раз. До смены владельца дождитесь подтверждения в журнале или встроенной координации.
- Если запись за пределы проекта запрещена, используйте встроенные сообщения между агентами. Не обходите ограничение песочницы.

## Сохранение проекта

- Перед изменением проверьте git status и git diff именно по затрагиваемым файлам.
- Сохраняйте все существующие пользовательские правки. Не выполняйте git reset, git checkout, git clean и не восстанавливайте файлы без прямого поручения.
- Не восстанавливайте удалённую сборку iPod.app и не удаляйте неизвестные артефакты, пока координатор не выяснит их назначение.
- Перед передачей результата укажите точные файлы, причину изменения, выполненные проверки и оставшиеся ограничения.
- Не публикуйте GitHub Pages, не меняйте удалённый репозиторий, не подписывайте и не устанавливайте приложение без отдельного поручения.

## Владение областями

- Координатор отвечает за интеграцию, README.md и AGENTS.md.
- Агент клиента отвечает за app.js, index.html, styles.css и sw.js.
- Агент сервера отвечает за server.js и tests/sync.test.js.
- Агент macOS отвечает за macOS/source/** и Start iPod Sync.command.
- При общем рабочем дереве не редактируйте файл, которым уже владеет другой агент. Сначала согласуйте передачу через чат.txt.

## Сеть, сервер и данные

- Перед запуском проверяйте порт 3443 и состояние текущего сервера. Не запускайте второй сервер и не останавливайте существующий процесс без прямого поручения.
- Не меняйте сохранённый порт или URL профиля без одновременного обновления профиля и проверки, что ссылка останется стабильной между перезапусками.
- Не заменяйте route-aware IPv4 на hostname.local без проверки разрешения имени, TLS-сертификата и доступности с iPhone.
- Пользователь разрешил только бесплатный вариант. До подтверждения условий не передавайте аудио через публичный Cloudflare hostname; предпочтительный вариант для проверки — частный Tailscale Serve, без Funnel.
- Не выводите токены, ключи и содержимое файлов учетных данных в логи, чат или ответ пользователю.
- Для аудиофайлов учитывайте, что публичный relay передаёт данные через провайдера; сообщайте владельцу проекта о лимитах тарифа и условиях сервиса до настройки.
- AirDrop остаётся вариантом без локального сервера и сертификата; это пакетный импорт через Files, а не автоматическое обнаружение новых песен.

## Проверки и продолжение

- Не запускайте тесты и сборки, если пользователь не просил проверить результат. Если проверка поручена, её запускает один ответственный агент и записывает результат.
- Не прекращайте согласованную работу до результата или явной просьбы остановиться. При блокировке доступа продолжайте независимую диагностику и точно сообщите, что заблокировано.
