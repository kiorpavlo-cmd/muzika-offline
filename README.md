# Музика

Мобільний офлайн‑орієнтований музичний вебзастосунок. Інтерфейс відтворює навігацію й темну тему з наданих зображень; комп'ютерний макет можна додати окремо.

## Що вже працює

- PWA встановлюється на телефон із браузера.
- Оболонка застосунку кешується і відкривається без мережі.
- Під час запуску застосунок перевіряє сервіс‑воркер і завантажує оновлені файли, якщо вони є. Без мережі використовує останню збережену версію.
- Потягніть екран вниз від самого верху, щоб примусово завантажити свіжу офлайн‑оболонку й перезапустити застосунок. Старий кеш оболонки замінюється лише після успішного завантаження; пісні та налаштування залишаються на пристрої.
- Музичні файли можна додати з пристрою. Вони зберігаються локально в браузері та відтворюються офлайн.
- Пошук перевіряє локальну медіатеку та показує глобальні результати YouTube прямо у застосунку; онлайн‑каталог і відтворення потребують інтернету.
- Профіль можна під'єднати через Google; музика при цьому залишається на пристрої.
- `Muzika.mobileconfig` додає ярлик застосунку на головний екран iPhone або iPad і використовує іконку проєкту.

## CarPlay

Після запуску пісні в ярлику **Music** відкрийте на екрані CarPlay системний екран **Now Playing**. Застосунок передає iOS назву треку та команди відтворення, паузи, перемикання і пошуку по позиції. Це дає доступ до поточної пісні через системний плеєр CarPlay, але не додає окрему іконку Music і не відкриває бібліотеку на екрані авто. Для окремої іконки та перегляду бібліотеки потрібен нативний iOS-застосунок із дозволом CarPlay Audio від Apple.

Каталог у демонстрації — зразок інтерфейсу без аудіозаписів. Щоб відтворювати музику, додайте власні аудіофайли через **Медіатека → +**. Назву й виконавця можна вказати у назві файлу як `Виконавець — Пісня.mp3`.

## Локальний запуск

Сервіс‑воркери працюють через HTTPS або `localhost`. У папці проєкту виконайте:

```sh
python3 -m http.server 8000
```

Потім відкрийте `http://localhost:8000`.

## Публікація на GitHub Pages

У репозиторії вже є GitHub Actions workflow для публікації статичного застосунку. Після push гілки `main` відкрийте **Settings → Pages** та виберіть **GitHub Actions** як джерело. Публічна адреса матиме вигляд `https://<користувач>.github.io/<репозиторій>/`.

Локальні аудіофайли не завантажуються в GitHub і не синхронізуються між пристроями.

Профіль ярлика відкриває `https://kiorpavlo-cmd.github.io/muzika-offline/`. Після публікації його можна завантажити з налаштувань застосунку або за адресою `https://kiorpavlo-cmd.github.io/muzika-offline/Muzika.mobileconfig`.

## Google-вхід

Google-вхід використовується лише для профілю. Аудіофайли додаються з пристрою та залишаються у локальній офлайн-медіатеці; застосунок не запитує доступ до Google Диска.

YouTube Music не можна використовувати як джерело офлайн-аудіо в цьому застосунку. Офіційний YouTube Player працює онлайн, а правила YouTube API забороняють завантаження або кешування аудіовізуального вмісту для офлайн-відтворення та відтворення у фоні. Див. [YouTube API Developer Policies](https://developers.google.com/youtube/terms/developer-policies).

## Глобальний пошук

Пошук у вкладках **Найкращі результати**, **Виконавці** та **Альбоми** використовує YouTube Data API v3 і показує відео, канали та плейлисти YouTube безпосередньо в застосунку. Відтворення відбувається у вбудованому програвачі й потребує інтернету. Результати можна зберігати в медіатеку як онлайн-посилання; завантаження YouTube-аудіо в застосунку не підтримується. API YouTube не надає окремий повний каталог YouTube Music.

Ключ пошуку входить до офлайн-кешованого `app.js`. Він публічний і має бути обмежений доменом сайту та YouTube Data API v3 у Google Cloud Console. Не додавайте секрети OAuth у клієнтський код.
